# 使用
参考文件夹`example_problem`中的`README.md`来添加一个题目并测试提交。

# 介绍
整个系统使用容器部署，首次部署只需要运行

```bash
docker-compose up -d --build
```

部署成功可以用`docker-compose ps`看到下面的5个容器：
1. db：使用postgresql镜像作为整个系统的数据库
2. redis：使用redis做任务队列的管理
3. backend-api：管理后端API
4. backend-worker：接受backend-api的命令，利用宿主机dockerd来创建一个同级容器运行题目的测试
5. frontend：管理系统前端


部署时和环境相关的设置：
1. docker-compose.yml：
    1. 这个文件里规定了前端上传的文件（用户答案，题目测试脚本等）需要放在宿主机的什么位置，然后映射到容器中。这个变量是`HOST_UPLOAD_DIR`，在backend-worker的environment中设置，需要根据实际情况调整
    2. 前后端部署使用的端口，前端默认使用3000端口，后端默认暴露在8000端口。
        1. 前端修改：需要修改docker-compose.yml中对frontend的端口映射，比如如果想在宿主机中用3333端口，那么将`3000:3000`改成`3333:3000`。
        2. 后端修改：需要修改对backend-api的启动命令，同时需要注意frontend中使用的后端API URL需要同时调整。比如如果想用8888端口，那么启动命令中的8000变成8888，然后frontend的environment中`REACT_APP_API_URL=http://localhost:8888/api/v1`

如果需要添加问题，那么需要准备一个用于测试的镜像，然后准备一个用于测试的脚本。

# 设计

本系统只专注于下面这些事：
1. 接受用户对不同题目的答案提交，然后根据题目要求，使用测试镜像运行一个容器，将测试脚本作为这个容器的CMD，容器后直接执行这个脚本。
2. 系统完全不在意测试过程，系统只负责收集容器的logs，然后在最终的logs中解析是否有"SCORE: "字样，并把后面的数字作为分数存入数据库，显示在榜单中。其中日志也可以在榜单中看到。
3. 清晰的划分不同用户对于不同题目的不同次数的提交，这些提交保存在本代码根目录下的./data/uploads文件夹。提交的答案使用answer_前缀标记，报告使用report_前缀标记。具体结构：`uploads/{user_id}/{problem_id}/{uuid}/`
4. 让管理员可以管理用户，管理提交记录，管理题目。普通用户不能管理几乎任何东西，但是可以修改自己的密码。
5. 让系统一次只运行一个用户的测试请求，维护一个测试队列。
6. 提供看板，用户可以看到自己的和其他人的提交记录，包含分数、提交时间、提交的题目、用户名。不能看到其他人的日志。
7. 可以对提交记录做一些简单的过滤和排序，比如按照题目、用户名过滤，按照时间、成绩排序。

所有不在上面范围内的事情，都应该交给测试时完成。比如如何判断学生的得分。可以在测试脚本末尾运行"判断脚本"来判断这个学生应该拿多少分。

比如：
- 对于功能测试：完成功能就累计分数，最后"判断脚本"输出一个总分
- 对于带有指标的测试：对指标合理划分，利用函数曲线映射或者离散划分成绩，最后"判断脚本输出一个总分"

总之，测试脚本需要负责测试，并且计算这次有多少分，然后输出一个简单的"SCORE: xxx"告诉测试系统，这个同学的这次提交得了xxx分
